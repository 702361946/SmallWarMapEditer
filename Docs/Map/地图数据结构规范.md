# Small War 地图数据结构规范

> 基于 Assembly-CSharp.dll 反编译分析与 gMap 实例验证
> 版本: 2026-08-14

---

## 一、顶层结构: MapData

`MapData` 是地图文件的根对象，包含完整的地图定义。

| 字段                | 类型                 | 必填 | 说明                                |
|---------------------|----------------------|------|-------------------------------------|
| `width`             | `int`                | 是   | 地图宽度（X轴格子数）               |
| `height`            | `int`                | 是   | 地图高度（Y轴格子数）               |
| `type`              | `int`                | 是   | 地图类型编码，见 `MapType` 枚举     |
| `name`              | `string`             | 是   | 地图显示名称                        |
| `size`              | `int`                | 否   | 尺寸辅助参数，通常为 0              |
| `selectablePlayers` | `int[]`              | 是   | 可选玩家编号列表                    |
| `tileDataList`      | `TileData[]`         | 是   | 地形数据数组，长度 = width × height |
| `unitData`          | `EasyUnitData[]`     | 是   | 初始单位配置数组                    |
| `bothPlace`         | `Vector2[]`          | 是   | 双方可放置位置数组（含占位符）      |
| `playerDatas`       | `EasyPlayerData[]`   | 是   | 玩家配置数组，**索引 0 为保留位**   |
| `humanPlayerNumber` | `int`                | 是   | 人类玩家数量                        |
| `victoryConditions` | `VictoryCondition[]` | 否   | 胜利条件数组                        |
| `failureConditions` | `FailureCondition[]` | 否   | 失败条件数组                        |

---

## 二、地形数据: TileData

`TileData` 定义单个格子的地形属性。

```json
{
  "type": 10,
  "pos": { "x": 0.0, "y": 0.0 },
  "burning": false,
  "burningTime": 0
}
```

| 字段          | 类型      | 说明                                                 |
|---------------|-----------|------------------------------------------------------|
| `type`        | `int`     | 地形类型ID，通过 `Rule.GetCellData(id)` 查询完整规则 |
| `pos`         | `Vector2` | 偏移坐标 `{x, y}`，**非世界坐标**                    |
| `burning`     | `bool`    | 是否处于燃烧状态                                     |
| `burningTime` | `int`     | 燃烧剩余回合数                                       |

### 坐标规则

- `x` 范围: `[0, width-1]`
- `y` 范围: `[0, height-1]`
- 数组顺序: 通常按行优先（x 变化快，y 变化慢）
- 世界坐标转换: 由 `MapCreater.OffsetCoordToPosition(Vector3)` 处理

---

## 三、初始单位: EasyUnitData

`EasyUnitData` 定义地图加载时预置的单位。

```json
{
  "pos": { "x": 0.0, "y": 14.0 },
  "unitName": "BASE",
  "PlayerNumber": 1,
  "tag": "",
  "command": {
    "type": 0,
    "pos": { "x": 0.0, "y": 0.0 },
    "tag": ""
  }
}
```

| 字段           | 类型      | 说明                              |
|----------------|-----------|-----------------------------------|
| `pos`          | `Vector2` | 单位初始偏移坐标                  |
| `unitName`     | `string`  | 单位ID，对应 `UnitData.id`        |
| `PlayerNumber` | `int`     | 归属玩家编号，**有效值从 1 开始** |
| `tag`          | `string`  | 单位标签，供 AI 识别和筛选        |
| `command`      | `Command` | 初始 AI 命令                      |

### PlayerNumber 语义

| 值    | 含义                                      |
|-------|-------------------------------------------|
| `0`   | **系统保留/无归属**，不参与 AI 与人工操作 |
| `1~8` | 正常玩家编号，对应 `playerDatas[1~8]`     |

> **重要**: `unitData` 中不应出现 `PlayerNumber = 0` 的单位。若需放置中立对象（如城市、资源点），应通过地形或其他机制实现，而非单位系统。

## 四、玩家配置: EasyPlayerData

`EasyPlayerData` 定义每个玩家的初始状态。

```json
{
  "playerNumber": 1,
  "team": 0,
  "money": 1000,
  "techPoint": 0,
  "camp": "US",
  "unitPlayerNumber": 0,
  "landUnits": [],
  "skyUnits": [],
  "shipUnits": [],
  "lockTechs": [],
  "lockUnits": [],
  "lockUpgrade": [],
  "type": 1,
  "color": 0
}
```

| 字段               | 类型       | 说明                                |
|--------------------|------------|-------------------------------------|
| `playerNumber`     | `int`      | 玩家编号，**0 为系统保留位**        |
| `team`             | `int`      | 队伍编号，同 team 为盟友            |
| `money`            | `int`      | 初始金钱                            |
| `techPoint`        | `int`      | 初始科技点                          |
| `camp`             | `string`   | 阵营ID，如 `"US"` `"TypeA"` 等      |
| `unitPlayerNumber` | `int`      | 单位子编号，通常为 0（未使用/遗留） |
| `landUnits`        | `string[]` | 初始解锁陆军单位ID列表              |
| `skyUnits`         | `string[]` | 初始解锁空军单位ID列表              |
| `shipUnits`        | `string[]` | 初始解锁海军单位ID列表              |
| `lockTechs`        | `string[]` | 锁定科技ID列表                      |
| `lockUnits`        | `string[]` | 锁定单位ID列表                      |
| `lockUpgrade`      | `string[]` | 锁定升级ID列表                      |
| `type`             | `int`      | 玩家类型编码                        |
| `color`            | `int`      | 颜色索引 0~8                        |

### Player 0 保留位规范

`playerDatas[0]` 是 **系统保留位**，具有以下特征：

- `playerNumber`: 固定为 `0`
- 不拥有任何单位（`unitData` 中无 `PlayerNumber = 0`）
- 不参与回合轮转
- 不执行 AI 逻辑
- 不响应人工操作
- 可能用途：
    - 中立建筑/环境对象的逻辑归属
    - 系统事件触发器
    - 地图特效（燃烧、迷雾）的持有者
    - 占位符，保持数组索引与逻辑编号对齐

### 玩家类型编码

| 值   | 类型     | 说明                          |
|------|----------|-------------------------------|
| `1`  | 人类玩家 | 由本地/联机玩家控制           |
| 其他 | AI 玩家  | 由 `NewAiPlayer` 及其子类控制 |

## 五、命令结构: Command

`Command` 定义单位的初始行为指令。

```json
{
  "type": 0,
  "pos": { "x": 0.0, "y": 0.0 },
  "tag": ""
}
```

| 字段   | 类型      | 说明                 |
|--------|-----------|----------------------|
| `type` | `int`     | `CommandType` 枚举值 |
| `pos`  | `Vector2` | 命令目标坐标         |
| `tag`  | `string`  | 命令标签，供 AI 筛选 |

### CommandType 枚举

| 值  | 名称     | 说明                   |
|-----|----------|------------------------|
| `0` | `None`   | 无命令，单位待机       |
| `1` | `Move`   | 移动至目标坐标         |
| `2` | `Attack` | 攻击目标               |
| `3` | `Defend` | 防御姿态               |
| `4` | `Alert`  | 警戒/伏击              |
| `5` | `Free`   | 自由行动（AI全权决策） |

## 六、可放置位置: bothPlace

`bothPlace` 是 `Vector2` 数组，定义玩家的合法出生/放置位置。

### 格式规范

```text
[
  { "x": 255.0, "y": 255.0 },    // [0] 保留位/占位
  { "x": 0.0,   "y": 14.0 },     // [1] P1 基地位置
  { "x": 1.0,   "y": 14.0 },     // [2] P2 基地位置
  { "x": 255.0, "y": 255.0 },    // [3~8] 未使用占位
  ...
]
```

### 哨兵值

| 值           | 含义                                      |
|--------------|-------------------------------------------|
| `(255, 255)` | **无效/未使用位置**，固定长度数组的占位符 |
| 其他坐标     | 有效放置位置，对应 `playerDatas` 索引     |

### 数组索引语义

| 索引  | 对应玩家           | 说明                      |
|-------|--------------------|---------------------------|
| `0`   | 系统保留           | 无实际意义                |
| `1~8` | `playerDatas[1~8]` | 该玩家的主基地/出生点坐标 |

> **重要**: `bothPlace` 长度固定为 9（与 `playerDatas` 长度一致），无效位必须用 `(255, 255)` 填充，不可省略。

## 七、胜负条件

### VictoryCondition

```json
{
  "condition": 0,
  "arg1": "",
  "arg2": "",
  "pos": { "x": 0.0, "y": 0.0 }
}
```

| 字段        | 类型      | 说明                              |
|-------------|-----------|-----------------------------------|
| `condition` | `int`     | `VictoryCondition.Condition` 枚举 |
| `arg1`      | `string`  | 条件参数1                         |
| `arg2`      | `string`  | 条件参数2                         |
| `pos`       | `Vector2` | 条件关联坐标                      |

### VictoryCondition.Condition 枚举

| 值  | 名称                     | 说明                     |
|-----|--------------------------|--------------------------|
| `0` | `DestroyAllEnemyPlayers` | 消灭所有敌方玩家         |
| `1` | `DestoryOnePlayer`       | 消灭任一玩家（拼写保留） |
| `2` | `DestroyTargetUnit`      | 摧毁目标单位             |
| `3` | `StickTo`                | 坚守至指定回合           |
| `4` | `UnitMoveTo`             | 单位移动至目标位置       |

### FailureCondition

结构与 `VictoryCondition` 完全相同，仅语义相反：满足条件即失败。

| 值  | 名称                        | 说明                 |
|-----|-----------------------------|----------------------|
| `0` | `DestroyAllFriendlyPlayers` | 所有友方玩家被消灭   |
| `1` | `DestoryOnePlayer`          | 任一友方玩家被消灭   |
| `2` | `DestroyTargetUnit`         | 目标单位被摧毁       |
| `3` | `StickTo`                   | 未坚守至指定回合     |
| `4` | `UnitMoveTo`                | 单位未移动至目标位置 |

## 八、辅助结构: Vector2

```json
{ "x": 0.0, "y": 0.0 }
```

| 字段 | 类型    | 说明         |
|------|---------|--------------|
| `x`  | `float` | 水平偏移坐标 |
| `y`  | `float` | 垂直偏移坐标 |

### 坐标体系区分

| 类型                 | 使用场景                                 | 转换方法                             |
|----------------------|------------------------------------------|--------------------------------------|
| `Vector2` (偏移坐标) | 地图文件、网络同步、AI配置、TileData.pos | —                                    |
| `Vector3` (世界坐标) | `MapCreater` 实例化、Unity 场景对象      | `MapCreater.OffsetCoordToPosition()` |

## 十、数据校验规则

### 必填校验

| 校验项                    | 规则                                                    |
|---------------------------|---------------------------------------------------------|
| `tileDataList.length`     | 必须等于 `width × height`                               |
| `bothPlace.length`        | 必须等于 `playerDatas.length`（通常为 9）               |
| `selectablePlayers`       | 所有值必须在 `[1, playerDatas.length-1]` 范围内         |
| `unitData[].PlayerNumber` | 必须在 `[1, playerDatas.length-1]` 范围内，**不可为 0** |
| `bothPlace[0]`            | 应为 `(255, 255)` 占位                                  |

### 一致性校验

| 校验项                        | 规则                                                      |
|-------------------------------|-----------------------------------------------------------|
| `playerDatas[i].playerNumber` | 必须等于数组索引 `i`                                      |
| `playerDatas[0].playerNumber` | 必须为 `0`                                                |
| `unitData[].pos`              | 必须在地图边界内：`[0, width-1]` × `[0, height-1]`        |
| `bothPlace[i]`                | 若不为 `(255, 255)`，则对应 `playerDatas[i]` 应为有效玩家 |

### 哨兵值规范

| 场景               | 哨兵值       | 含义           |
|--------------------|--------------|----------------|
| `bothPlace` 无效位 | `(255, 255)` | 该玩家位未启用 |
| `unitPlayerNumber` | `0`          | 未分配子编号   |
| `command.type`     | `0`          | 无初始命令     |

## 十一、Mod 开发建议

### 生成自定义地图

```csharp
// 1. 创建 MapData
MapData mapData = new MapData();
mapData.width = 20;
mapData.height = 20;
mapData.type = (int)MapType.Continent;
mapData.name = "MyMap";

// 2. 填充 tileDataList（必须完整填充 width×height）
mapData.tileDataList = new List<TileData>();
for (int y = 0; y < mapData.height; y++)
{
    for (int x = 0; x < mapData.width; x++)
    {
        mapData.tileDataList.Add(new TileData
        {
            type = 10,  // 平地
            pos = new Vector2(x, y),
            burning = false,
            burningTime = 0
        });
    }
}

// 3. 配置 playerDatas（必须包含索引 0 的保留位）
mapData.playerDatas = new List<EasyPlayerData>();
// [0] 系统保留位
mapData.playerDatas.Add(new EasyPlayerData
{
    playerNumber = 0,
    team = 0,
    money = 0,
    camp = "",
    type = 1,
    color = 0
});
// [1] P1
mapData.playerDatas.Add(new EasyPlayerData
{
    playerNumber = 1,
    team = 0,
    money = 1000,
    camp = "US",
    type = 1,
    color = 0
});

// 4. 配置 bothPlace（长度必须与 playerDatas 一致）
mapData.bothPlace = new List<Vector2>();
mapData.bothPlace.Add(new Vector2(255, 255));  // [0] 保留
mapData.bothPlace.Add(new Vector2(0, 19));      // [1] P1 出生点

// 5. 放置初始单位（PlayerNumber 从 1 开始）
mapData.unitData = new List<EasyUnitData>();
mapData.unitData.Add(new EasyUnitData
{
    pos = new Vector2(0, 19),
    unitName = "BASE",
    PlayerNumber = 1,  // 归属 P1，不可为 0
    tag = "",
    command = new Command { type = 0, pos = Vector2.zero, tag = "" }
});

// 6. 保存
SaveManager.SavaPlayerMap(mapData, "MyMap", mapData.type);
```

### 关键注意事项

1. **Player 0 不可用于单位归属**——`unitData` 中所有 `PlayerNumber` 必须 ≥ 1
2. **数组长度严格匹配**——`bothPlace.Length == playerDatas.Length == 9`
3. **tileDataList 必须完整**——缺失或多余都会导致 `CreateMap()` 崩溃
4. **地形 type 必须有效**——`Rule.GetCellData(type)` 必须返回非 null
5. **坐标边界检查**——所有 `pos` 必须在 `[0, width-1] × [0, height-1]` 内
